# Pre-Install Key-Free Native Capabilities Behind Declarative Manifest Permission Gates

We pre-install a comprehensive "batteries-included" suite of key-free native `Capability Module`s (camera/scanner, photo/media picker, file/share, hybrid WebView with JSBridge, biometrics, location, notifications, audio/video, keyboard/bottom-sheet/network utilities) so derived App Instances subtract rather than assemble common mobile infrastructure; vendor-credentialed commercial SDKs (WeChat/Alipay, third-party maps/push) remain behind adapter interfaces to keep fresh clones immediately buildable. Because shipping unused `Info.plist` or `AndroidManifest.xml` permission declarations triggers App Store 5.1.1 and mainland China MIIT over-permission rejections, `app.config.ts` dynamically gates native permission registration from capability booleans in `App Identity`, and all runtime permission prompts pass through a synchronous `Permission Rationale` wrapper.
